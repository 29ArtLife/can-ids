# CAN-IDS

车载 CAN 总线的入侵检测研究，重点是**跨攻击类型的泛化能力**，而不是在简单数据集上刷准确率。

> 大学生创新训练计划项目 · 研究进行中，结论尚未形成

## 为什么做这个

现代汽车内部由数十个电子控制单元通过 CAN 总线通信。CAN 协议设计于上世纪八十年代，只考虑可靠性，没有身份认证与加密——总线上的任何设备都可以发送报文，接收方默认信任。攻击者一旦接入总线（OBD 接口、车载娱乐系统、远程通道），就能伪造刹车、油门等关键指令。

车载入侵检测已有大量研究，但存在两个明确的问题：

1. **评测数据过于简单**。多数工作在 Car-Hacking 数据集上报告 99% 以上的准确率，而该数据集的攻击模式高度规整，仅靠报文频率就能区分。
2. **跨攻击泛化能力不足**。文献表明，在留一种攻击类型作为测试集的条件下，现有模型性能会显著下降，部分方法退化到接近随机猜测。

本项目不追求刷高单数据集指标，而是量化"方法在未知攻击与真实数据上会失效多少"，并尝试针对周期稳定性做特征改进。

## 数据集

本项目使用以下公开学术数据集，不涉及企业数据与个人隐私：

| 数据集 | 说明 |
|---|---|
| Car-Hacking (HCRL) | 最常用的 CAN 攻击基准，含 DoS、模糊、欺骗、重放四类攻击 |
| ROAD | 目前最接近真实场景的 CAN 入侵数据集 |
| CAN-Train-and-Test | 面向跨域与泛化测试设计 |
| VeReMi / VeReMi Extension | V2X 车外通信虚假消息数据 |

数据集不随仓库分发，请从各官方发布页获取后放入 `data/raw/`。

## 评测协议

三类测试，逐级加难：

| 协议 | 训练 / 测试 | 目的 |
|---|---|---|
| 同分布 | 相同攻击类型 | 确认流程与基线水平 |
| LOAO | 留一种攻击类型仅在测试出现 | 评估对未知攻击的识别能力 |
| 跨数据集 | 一个数据集训练，另一个测试 | 评估真实场景下的性能衰减 |

核心指标为 F1、召回率与误报率。**不使用准确率作为主要指标**——类别不平衡条件下准确率没有意义。

## 环境

```bash
python 3.11
pip install -r requirements.txt
```

主要依赖：pandas、scipy、scikit-learn、LightGBM、PyTorch、FastAPI。

无 GPU 需求，模型规模控制在笔记本 CPU 可训练范围内。

## 目录结构

```
can-ids/
├── data/
│   ├── raw/           # 原始数据集（不入库）
│   ├── interim/       # 统一格式的中间文件
│   └── processed/     # 切分好的训练/测试集
├── configs/           # 实验配置
├── src/
│   ├── io/            # 各数据集解析器
│   ├── features/      # 特征工程
│   ├── models/        # 基线与改进模型
│   ├── experiments/   # 训练与评测入口
│   └── api/           # 检测原型
├── results/
│   ├── runs.csv       # 每次实验一行，完整记录
│   └── figures/
└── docs/
```

## 实验记录约定

所有实验必须向 `results/runs.csv` 追加一行，包含时间、配置、数据集、留出的攻击类型、模型、随机种子与各项指标。缺记录的实验视为未完成。

关键约束：

- 窗口切分时，同一时间段的数据不得同时出现在训练集与测试集
- 跨数据集实验时，目标数据集不得参与任何训练或调参
- 过采样只在训练集内部进行
